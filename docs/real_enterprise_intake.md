# 真实企业样本接入流程（T008 / T038）

这是验收清单里最后一块硬骨头：**1 家真实企业手填复算，与公开评测结论一致**。
合成层再完整也替代不了这一步——合成层只能证明规则实现没有系统性偏差。

## 三条硬规矩

1. **真实企业数据不进公开仓库**。本站是 GitHub Pages 公开站，`data/` 目录所有人可见；
   真实企业画像、经营数据与公开评测结论截图**不要提交进本仓库**，也不要传到公开的后端实例。
   需要留痕时，只提交**脱敏后的结论摘要**（等级、一致与否、差异原因），原始数据留在本地。
2. **只认公开来源**。公开评测结论要能给出链接或出处（平台公示、公示名单、公开报道）。
   拿不到出处的结论不能作为验收依据。
3. **不一致要写清原因**，不能改判据迁就结论。等级判定的口径是官方文件，
   复算与公开结论不一致时，先查是不是场景等级自评与公开评定的差异。

## 流程

### 第 1 步：选企业

- 优先选**有公开评测结论**的企业：工信部"优质中小企业梯度培育平台"的数字化水平评测结果、
  各地数字化转型试点的公示名单、或公开报道中明确给出评测等级的。
- 先只做 1 家，做通流程再扩。

### 第 2 步：填记录

复制模板：

```bash
cp data/profiles/real_template.json data/profiles/real_001.json
```

要填的字段：

| 字段 | 填什么 | 必填 |
|---|---|---|
| `name` | 企业名称 | 是 |
| `provenance` | 数据来源与获取方式 | 是 |
| `source.public_conclusion_url` | 公开评测结论的链接或出处 | 是 |
| `source.evaluated_by` / `evaluated_at` | 公开结论的评测主体与时间 | 是 |
| `published_conclusion.level` | 公开结论给出的等级（1—4 或 null 表示无等级） | 是 |
| `published_conclusion.level_name` | 公开结论的等级名称 | 建议 |
| `published_conclusion.total_score` | 公开结论的总分（没有就留空） | 否 |
| `profile.answers` | 15 个采集项的答案，**照官方选项原文填** | 是 |
| `profile.scenario_levels` | 16 个场景的等级（S01—S16） | 是 |
| `profile.*_wan` 等 | 经营基线（留空不影响定级，只影响投入产出测算） | 否 |

> 采集项答案必须用 `precomputed/criteria.json` 里的**选项原文**，不能自己改写措辞。
> 填完可以用 `python3 scripts/verify_criteria.py` 之外的方式自查：
> `python3 scripts/recompute_profile.py data/profiles/real_001.json --payload` 会打印逐项得分。

### 第 3 步：复算比对

```bash
python3 scripts/verify_real_recompute.py data/profiles/real_001.json
```

它会输出等级、总分、场景数与约束性场景数的对照，并给出结论：

- 退出码 0：一致 → 可写入评测报告的真实层；
- 退出码 1：不一致 → 按差异原因分三类记清楚：
  - **场景等级自评差异**：公开评测的场景等级与你的自评不同（最常见，占多数）；
  - **口径版本差异**：公开结论用的是 2022 版指标，现在是 2024 版；
  - **答案理解差异**：某个采集项的选项理解不同（附上该项的两种理解与得分差）。
- 退出码 2：记录没填完。

### 第 4 步：写进评测报告

在 `data/evaluation/report.json` 的 `layers.real` 里登记真实层（家数、来源、复算结论），
并让报告的"真实层"从 `0 家`变成实际数字。**不要把真实企业的原始画像提交进仓库**，
只提交结论摘要。

## 做完之后的连带影响

- **T008 完成**：真实企业复算记录（一致/不一致 + 原因）。
- **T038 完成**：评测报告真实层不再是 0 家。
- **T045 可测**：ROI 测算偏差有了真值参照——用真实企业的公开投入产出数据做参照，
  与系统的 ROI 区间比对，偏差才真正有意义。
- **T043 可复核**：若拿到一两位专家标注的"应该先做什么"顺序，
  就能用 `docs/decisions/T043_ranking.md` 里的方法做人工参考顺序复核。
