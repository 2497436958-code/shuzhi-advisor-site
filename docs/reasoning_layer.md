# 推理层口径说明

推理层负责把一份画像变成四段式结论：**诊断 → 路径 → 排序与不建议做 → 政策注记**。

原则（与主控文档一致）：

- 算分、定级、ROI 全部由确定性代码完成，模型不参与计算；
- 每条结论必须带证据链，缺证据不允许输出（`advisor.reasoning.evidence.ensure_evidence`）；
- 判据、门槛、ROI 口径不得由模型改写。

## 模块

| 模块 | 文件 | 职责 |
|---|---|---|
| 判据层 | `src/advisor/scoring/engine.py`、`thresholds.py` | 算分、定级（未改动） |
| 反模式 | `src/advisor/reasoning/antipatterns.py` | AP1—AP4 检测 |
| 诊断 | `src/advisor/reasoning/diagnosis.py` | 四类瓶颈 + 证据链 |
| 路径 | `src/advisor/reasoning/pathway.py` | 选步、依赖顺序、验收口径 |
| 排序 | `src/advisor/reasoning/ranking.py` | ROI 区间、等级跃迁分、优先级 |
| 证据 | `src/advisor/reasoning/evidence.py` | 证据构造与强制闸门 |
| 流水线 | `src/advisor/reasoning/pipeline.py` | 组装与站点已发布预计算结果同构的结果体 |

## 诊断规则

| 瓶颈类型 | 触发条件 | 命中采集项 | 命中场景 |
|---|---|---|---|
| 基础断层·设备侧（AP1） | 采集项 2 ≥(40%,60%] 且采集项 3 ≤(10%,20%] | 2、3 | S08 设备管理 |
| 流程空转·系统已上（AP2） | 采集项 5 覆盖绝大部分或全覆盖，且生产管控/质量管理仍为一级 | 5 | S06、S07 |
| 数据沉底·只采不析（AP3） | 采集项 4 覆盖环节数 ≥6，且决策支持仍为一级 | 4 | S16 决策支持 |
| 投入错配·重投入轻能力（AP4） | 采集项 11 ≥(20%,40%] 且总分 <40 | 11 | — |
| 场景断层·约束性场景未进阶 | 存在约束性场景仍为一级 | — | 全部卡住的一级约束性场景 |
| 等级缺口 | 下一个够不到的等级 | 得分缺口最大的 3 个采集项 | — |
| 基础缺口·一级指标 | 数字化基础维度得分低于该维度权重的一半 | 该维度内得分不足一半的采集项 | — |

`max_score_gain` = Σ（该采集项三级权重 ×（100 − 该项得分）），单位是总分里的分。

## 选步规则

1. 弱场景 = 当前等级低于 2 级的场景；
2. 一个场景只提一个改造项：优先**场景专属动作**，底座动作只补没有专属动作的场景；
3. 按优先级 P 取前 6 步，并强制补齐前置依赖；
4. 步骤顺序 = 依赖深度优先，同层按 P 降序。

优先级（主控文档第 8 节）：

```text
P = (等级跃迁分 + 关联成效改善) ÷ 投入成本
```

其中等级跃迁分是该改造项相关采集项的可回收分数，关联成效改善取收益区间下界。
两个分子项单位不同（分 / 万元），P 只用于同一依赖层内排序，不作为业务结论数。

## ROI 口径

```text
ROI = 预期可量化成效收益 ÷ 投入成本
收益区间 = Σ（收益基数[采集项 12—15] × 成效弹性区间）
ROI 下界 = 收益下界 ÷ 成本上界
ROI 上界 = 收益上界 ÷ 成本下界
```

排序取**下界**（保守）。补贴不进分子。

规模折算：投入区间与收益基数都按营业收入等比折算（基准 6000 万元营收），
**分子分母必须用同一个系数**，ROI 才是比值、不随企业规模变化。
（评测过程中发现过"分子折算、分母没折算"的实现错误，已修正。）
**该折算律尚未用真实企业校准，待人工确认。**

## 与已发布预计算结果的差异

判据层 100% 一致（6 个样例逐字段相同），反模式命中一致，诊断条目一致，
共同改造项的 ROI 数值完全一致。

路径段有两处**有意差异**，原因是生成预计算结果的脚本已经丢失、无法复原：

1. **选步集合**：预计算用的是当时的"变体选择"启发式（同一 path 编号在不同样例里
   对应不同改造项，见 `data/pathways.json` 的 `conflicts`）；推理层改用上面写明的
   确定性规则，一个场景只提一个改造项。
2. **步骤顺序**：预计算按依赖拓扑与当时的内部顺序混合；推理层按依赖深度 + P 排序。

另有两条口径冲突**待人工裁决**，本轮没有擅自改：

- 引擎仓 `feature/knowledge-p2` 有一套更新、更完整的 32 条归因路径表，
  编号含义与站点现用的路径表不同（例如两边的 PATH-011 指向不同场景）。
  本轮推理层只用站点现用的路径表，避免同一编号两种含义。
- 引擎仓的成效弹性表（`data/knowledge/elasticity.json`）有公开案例支撑，
  但与站点预计算用的演示弹性区间不同。本轮沿用站点口径并显式披露"未被公开案例支撑"。
