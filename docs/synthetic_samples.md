生成器：`scripts/generate_synthetic_profiles.py`。

## 构造规则

每条样本由"基线画像 + 目标 archetype 覆盖 + 同档位变体"三步得到：

1. **基线**：二级规范级企业的 15 采集项答案 + 16 场景等级（多数二级，5 个一级留改造空间）；
2. **覆盖**：按 archetype 把目标采集项与场景改到判据命中位，例如
   AP1 把采集项 2 设到 `(60%,100%]`、采集项 3 设到 `[0-10%]`、S08 压到一级；
3. **变体**：只在**同一得分档位**内替换选项（多选换选中项但不改数量，单选不换），
   再让规划实施、资金保障、成效项各换一档，于是同组内出现不同得分与等级。

生成器写完会用引擎复核每一条：命中的反模式必须与构造意图完全一致，等级必须落在该 archetype 的预期区间内；任何一条不一致就直接报错、不落盘。

## 每条样本带什么

```json
{
  "id": "SYN-AP1-01",
  "archetype": "AP1",
  "synthetic": true,
  "industry": "电子电器",
  "scale": "中型",
  "expected": {
    "antipatterns": ["AP1"],
    "diagnosis_types": ["基础断层·设备侧"],
    "bottleneck_scenarios": ["S08"],
    "action_ids": ["P-NET", "P-SEC", "P-ENERGY", "P-PLAN"]
  },
  "actual": { "total_score": 46.86, "level": 2, "level_name": "规范级", "antipatterns": ["AP1"] },
  "profile": { "answers": {}, "scenario_levels": {}, "revenue_wan": 0 }
}
```

- `expected`：**按构造应当**命中的反模式、诊断类型与改造项。
  其中 `action_ids` 是"仍在一级的场景所对应的改造项"，直接取自
  `data/pathways.json` 的场景—改造项映射，与推理层的选步规则无关，
  可直接用来算归因路径命中率（T042）。
- `actual`：**引擎实测**结果，用来核对构造意图，也用来算检出率与误报率（T044）。

## 已知边界

1. **样本不覆盖 7 个场景**：路径表只覆盖 S01/S03/S06—S11/S16，
   S02/S04/S05/S12—S15 没有对应改造项，这 7 个场景的改造建议无法用样本验证。
2. **对照组不是"完美企业"**：对照组也留了 5 个一级场景，
   用于验证"该提的改造项提得出来、不该提的不提"。
3. **成效弹性仍是演示口径**：样本只验证诊断与路径，
   ROI 测算偏差（T045）要在真实企业样本（T038）上才有意义。
4. **合成样本的分布不等于真实企业分布**：真实企业要以 T038 的手填复算为准，
   合成层只能证明"规则实现没有系统性偏差"，不能证明"业务结论正确"。
